# 来源和验证范围

来源类别：官方自述 `official_statement`、代码检查 `code_inspection`、历史测试 `historical_test`、本次实测 `current_test`、作者推断 `inference`。

验证范围：资料 `materials`、版本许可 `version_license`、PoC `poc`、项目集成 `project_integration`、运行验收 `runtime`。结果可为通过、失败、部分通过或未执行；数据性质、具体版本、日期和历史/本次标记分别登记。

- 社区版初始卡片的来源登记为作者编制与外部参考，统一待复核。参考 URL 不等于取得了网页正文；来源文件 SHA256 只用于包内完整性。
- PoC、集成和运行的执行结果必须关联历史或本次测试。官方说明、代码检查和推断不能单独证明运行成功。
- 本次通过要有本次实测及退出码；历史结果不能改成当前，模拟样本不能变成真实业务结果。
- 自动收录不升级验证级别。结论冲突并列保留，替代结论关联原记录，约束改变标记待复核。
- 不能访问来源时列出缺口，不编造结果；不建立定时抓取。

`validate` 检查结构和证据类型约束，不评判文字语义真实、来源可信度、数据是否真的合成或许可是否有效。人工与 Agent 审阅仍必需。

新来源需填写 ID、类别、位置、日期、版本/指纹、说明与包内快照。未知来源日期填写 `source_date: null` 和 `date_note`。本次实测另填 `command` 和 `exit_code`；正文中保留复现环境、输入、预定标准、结果与限制。

## 日期与时区

`catalog.json` 的 `date_utc_offset` 指定日期记录所用的 UTC 偏移，当前为 `+08:00`。日期校验使用该偏移的当前日期，避免读者机器处于其他时区时误报未来日期。未提供该字段的旧目录仍使用本机日期；来源的原始时区未知时应在说明中保留缺口。
