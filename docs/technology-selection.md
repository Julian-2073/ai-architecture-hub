# 技术选型怎么判断

1. 先确认用户、输入、操作、输出、数据性质与成功标准。
2. 检查目标项目的现有实现、依赖、锁文件与部署约束，能复用就复用。
3. 以能力地图和卡片寻找条件性候选，只比较最相关的两三条路线；资产制作、运行渲染、业务模拟等不同层不能当作同类替代品。
4. 针对真正缺口查当前官方文档和仓库。最终候选核对目标版本、许可、维护、部署、费用与退出条件，引用支持具体结论的来源。
5. 只有会改变选择的未知项才做最小 PoC，事先约定数据、环境、通过标准和停止条件。
6. 推荐一条路线，说清适用原因、代价、迁移和重新评估条件，提供模块、接口、实施任务与验收。
7. 实施后回写真实证据，失败也保留；模拟、历史和当前验收不能混用。
