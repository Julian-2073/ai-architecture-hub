# 示例交接：本地 CSV 销售分析工作台

状态：设计示例，未编码、未执行验收；以下数据与性能目标都是明确的示例假设，不是真实业务成绩。

## 用户原话与验收

“我想上传销售 CSV，在网页按日期和品类筛选，看销售额、订单数和趋势，导出筛选结果，数据不要上传服务器。”

确认单人桌面浏览器、UTF-8 CSV、最大 10 MB、没有跨设备同步。示例字段：`date,order_id,category,quantity,unit_price`；销售额为 quantity × unit_price；订单数为不同 order_id 数；同一订单多行只算一次。金额按小数精确解析后转最小货币单位，拒绝超过两位的小数。日期为 ISO YYYY-MM-DD，筛选区间含首尾。

## 推荐及取舍

先评估浏览器本地解析、内存过滤聚合与少量图表；复用目标项目已有页面与图表组件。选择 Papa Parse 作为 CSV 解析候选，原因是 CSV 的引号、分隔符和换行不能可靠地用字符串切分。采用前核查目标版本、许可、浏览器兼容及真实样本；示例中尚未核查，不把候选写成最终依赖。

表格只做预览，原始记录保留在内存；默认不自动保存业务数据。数据不发到服务器，外部字体、遥测和 CDN 依赖也要检查，离线交付需本地打包资源。

替代路线：Python + DuckDB 适合更大数据和复杂查询，但增加本地运行环境；多人共享则需要后端、权限和持久化。文件规模或峰值内存不能满足、需要跨设备或后台任务时重新选型，不提前引入数据库与 Agent 框架。

## 模块与数据流

文件选择 → 编码/大小/字段校验 → CSV 解析 → 类型与行质量报告 → 内存数据集 → 日期/品类筛选 → 精确聚合 → 指标/趋势/预览 → 导出筛选记录。

模块职责：Import 处理文件和解析状态；Validation 报行号和原因；Dataset 保留合法类型及原值；Query 纯函数筛选；Metrics 纯函数聚合；View 展示状态；Export 按固定字段导出。主页面处理清空、重新导入和错误恢复。

## 数据与接口合同

```typescript
type SalesRow = { date: string; orderId: string; category: string;
  quantity: number; unitPriceMinor: number; sourceLine: number };
type RowIssue = { sourceLine: number; field: string; reason: string };
type Filter = { start?: string; end?: string; categories: string[] };
// parse(file) -> { rows, issues, blocked }
// filter(rows, Filter) -> SalesRow[]
// summarize(rows) -> { revenueMinor, distinctOrders, dailyRevenue }
// exportCsv(rows) -> UTF-8 Blob
```

必填空白与 0 区分，非整数数量、负数、无效日期、坏行和溢出明确报错。默认存在坏行阻止计算，用户明确选择“仅分析合法行”后，持续展示排除数量。导出防范以 `= + - @` 开始的文本被电子表格当公式；保留可回读的转义约定。

## 实施任务与验收

| 任务 | 交付 | 验收 |
|---|---|---|
| 导入与合同 | 解析、字段映射和质量报告 | 引号逗号、空白、0、坏日期、中文均有样本；坏行不静默消失 |
| 查询与聚合 | 独立过滤和指标函数 | 首尾日期、无结果、同订单多行、金额精度结果可人工对照 |
| 页面 | 上传、过滤、指标、趋势与错误 | 一次完整用户流程可操作；清空后旧值不残留 |
| 导出 | 筛选后 CSV | 行数、字段、金额与页面一致；重新导入可对照；公式文本不执行 |
| 目标环境检查 | 代表性文件和浏览器测量 | 以合成 10 MB CSV 在事先记录的设备测量，记录耗时/内存并与用户确认阈值比较 |
| 隐私与恢复 | 网络与错误行为检查 | 导入/查询/导出不发送文件内容；解析失败能重试，刷新丢失给出提示 |

## 关键 PoC 与未决项

优先验证最大样本在目标设备上的解析/聚合耗时与内存；开始前约定阈值，失败则停止扩大界面并评估 Worker、流式处理或本地数据库。小文件已满足时跳过独立 PoC。

未决项：实际字段、币种/税退货口径、编码、文件上限和浏览器版本需用户确认。此交接只提供足够明确的实现合同，不证明上述软件已完成。
