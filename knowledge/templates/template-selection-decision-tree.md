# 情境化技术选型决策树

适用：候选多、非技术用户难以分辨路线，或一个技术名对应不同使用方式。借鉴成熟架构中心的按工作负载决策方式，不复制供应商结论。

## 起点与停止条件

- 用户任务与目标结果：
- 现有实现、硬约束、预算与维护能力：
- 什么证据足以决定，不必继续比较？

| 决策问题 | 可观察依据 | 是：下一分支 | 否：下一分支 | 未知：最小取证 |
|---|---|---|---|---|
| 现有能力已足够？ | | 复用并验收 | 看实际缺口 | 只读相关实现 |
| 必须独立服务或平台？ | | 比较服务路线 | 评估库/原生能力 | 判断部署与状态边界 |
| 存在决定性兼容/质量风险？ | | 最小PoC | 正常实施 | 定义具体风险 |
| | | | | |

## 叶节点

| 推荐路径 | 适用条件 | 不能覆盖 | 成本与退出 | 版本和证据 | 重新评估触发 |
|---|---|---|---|---|---|
| | | | | | |

每个叶节点是一种情境化建议，不是对所有项目的采用排名。复杂决策可分多个短树，避免以无证据的加权总分掩盖硬约束。
