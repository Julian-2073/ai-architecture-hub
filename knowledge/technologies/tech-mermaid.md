# Mermaid

> 文本图示工具 · 产品建模与技术表达 · 候选，尚无本项目采用结论。

[返回索引](../../docs/technology-catalog.md) · [能力地图](../capabilities/cap-software-map.md) · [选型判断](../../docs/technology-selection.md)

## 它解决什么

把文本描述渲染为流程和关系图。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：文档架构图与可版本管理图示。
- **职责边界**：复杂自由排版和交互画布不是其重点。
- **选择分界**：文档图需要可版本管理和快速修改时采用；精确视觉排版或复杂白板交互另选工具。
- **比较入口**：Excalidraw；图形设计工具。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：参见能力地图中相邻的上下游能力。同域不等于等价，不必同时引入。

## 接入前提与接口

| 项目 | 接入时需要明确 |
|---|---|
| 建议能力接口 | 结构化文本 → 可编辑图示与导出图；这是业务职责示意，不是官方 API 签名 |
| 当前项目复用 | 检查已有实现、直接/传递依赖、锁文件、调用位置与平台原生能力 |
| 兼容重点 | 目标文档渲染器、中文字体、图示版本 |
| 目标版本 | 固定产品/发行版/版本，再核查文档；HEAD 不代表应直接用于生产 |
| 运行责任 | 谁提供运行环境、数据、权限、错误处理与长期维护 |

## 最小验证与验收重点

**决定性验证**：验证长标签、中文和目标文档渲染。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：渲染版本、字体和导出适配。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：图示源文本、主题和导出配置。标识实际使用的专有格式和平台能力，先验证导出与可重建性；不为所有依赖建立多余抽象。

当需求、规模、部署、团队能力、许可或支持状态改变，或关键验证不通过时重新评估。迁移工作量取决于项目使用深度，尚未测量。
