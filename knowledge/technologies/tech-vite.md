# Vite

> 前端构建工具 · Web 应用与构建 · 候选，尚无本项目采用结论。

[返回索引](../../docs/technology-catalog.md) · [能力地图](../capabilities/cap-software-map.md) · [选型判断](../../docs/technology-selection.md)

## 它解决什么

启动开发服务器并构建前端资源。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：需要现代前端工程开发与构建。
- **职责边界**：不是 UI 框架，也不是业务后端。
- **选择分界**：开发服务器与生产托管是两件事；部署需要检查 base path、资源和环境变量暴露。
- **比较入口**：框架自带工具；无需构建的 HTML。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[React](tech-react.md)、[Vue](tech-vue.md)、[Svelte](tech-svelte.md)、[Angular](tech-angular.md)。同域不等于等价，不必同时引入。

## 接入前提与接口

| 项目 | 接入时需要明确 |
|---|---|
| 建议能力接口 | 前端源码、模块、静态资源与构建配置 → 开发服务和可部署构建产物 |
| 当前项目复用 | 检查已有实现、直接/传递依赖、锁文件、调用位置与平台原生能力 |
| 兼容重点 | Node与包管理器版本、插件、目标浏览器、资源路径、环境变量与生产托管方式 |

| 运行责任 | 谁提供运行环境、数据、权限、错误处理与长期维护 |

## 最小验证与验收重点

**决定性验证**：构建后在目标环境运行并检查资源路径。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：插件兼容、构建体积与运行环境。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：源码、插件与构建配置、环境变量契约、资源路径和部署说明；业务状态、路由与数据语义由应用负责。
