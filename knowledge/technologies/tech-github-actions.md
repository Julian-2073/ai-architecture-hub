## 它解决什么

根据仓库事件执行构建测试与自动化。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：代码托管在 GitHub 且需要自动检查。
- **职责边界**：工作流可读不代表可安全接触部署秘密。
- **选择分界**：仓库事件驱动检查和交付可减少人工工作时使用；第三方 action、Runner 与秘密权限分别审查。
- **比较入口**：其他 CI；本地脚本。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[Docker](tech-docker.md)、[NGINX](tech-nginx.md)、[Caddy](tech-caddy.md)、[Kubernetes](tech-kubernetes.md)。同域不等于等价，不必同时引入。

## 接入前提与接口

| 项目 | 接入时需要明确 |
|---|---|
| 建议能力接口 | 代码、镜像或配置 → 可运行资源与交付流程；这是业务职责示意，不是官方 API 签名 |
| 当前项目复用 | 检查已有实现、直接/传递依赖、锁文件、调用位置与平台原生能力 |
| 兼容重点 | 平台架构、秘密、网络、持久卷、资源状态和授权 |
| 目标版本 | 固定产品/发行版/版本，再核查文档；HEAD 不代表应直接用于生产 |
| 运行责任 | 谁提供运行环境、数据、权限、错误处理与长期维护 |

## 最小验证与验收重点

**决定性验证**：验证不可信 PR 权限、缓存和失败状态。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：执行分钟、Runner、缓存和制品。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：声明配置、镜像来源、环境、状态备份和回退命令。标识实际使用的专有格式和平台能力，先验证导出与可重建性；不为所有依赖建立多余抽象。

当需求、规模、部署、团队能力、许可或支持状态改变，或关键验证不通过时重新评估。迁移工作量取决于项目使用深度，尚未测量。
