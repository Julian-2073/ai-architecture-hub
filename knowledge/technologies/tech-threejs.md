## 它解决什么

浏览器三维场景、相机与渲染。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：产品展示、数字展厅及定制 Web 3D。
- **职责边界**：不负责专业建模或自动构建仿真规则。
- **选择分界**：渲染、资产制作和业务模拟分别负责；先在真实目标设备评估模型、纹理和帧率。
- **比较入口**：Babylon.js；Godot Web 导出。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[Babylon.js](tech-babylonjs.md)、[Blender](tech-blender.md)、[Godot](tech-godot.md)。同域不等于等价，不必同时引入。

## 最小验证与验收重点

**决定性验证**：在目标手机验证模型加载和帧率。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：模型制作、加载、交互与性能优化。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 如何调用、交付什么

**调用类型**：应用内Web三维渲染库。

依据已有官方定位，把它作为网页运行层评估，由应用代码组织场景、资产与交互；不把它当建模软件。此次文档读取只得到导航，后续仓库路径不可用，未新增具体API证据。

| 交接项 | 需要落实 |
|---|---|
| 输入 | 可加载的资产或几何、相机/场景设置、对象身份与交互需求 |
| 输出 | 浏览器中的三维视图与交互状态；业务数据、资产制作和保存仍需应用实现 |
| 验收 | 在目标设备验证加载、材质、尺度、交互、资源释放和失效降级；离线渲染图不能代替实时运行验收 |
| 保留与接入责任 | 保留标准资产与业务对象接口。具体加载器、渲染器与目标版本API在实现前核查；不要根据本段安装全套三维工具。 |
