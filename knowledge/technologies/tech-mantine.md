# Mantine

## 它解决什么

提供表单、布局和交互组件。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：希望快速构建 React 应用界面。
- **职责边界**：不承担领域规则和数据访问权限。
- **选择分界**：评估目标表单、弹窗和数据展示的真实覆盖；比较主题和组件 API 的迁移成本，不仅看默认外观。
- **比较入口**：Ant Design；MUI。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[Tailwind CSS](tech-tailwind.md)、[Ant Design](tech-antd.md)、[shadcn/ui](tech-shadcn.md)、[Radix Primitives](tech-radix.md)。同域不等于等价，不必同时引入。

## 最小验证与验收重点

**决定性验证**：用实际表单和列表验证能力。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：主题、依赖与组件升级。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：业务组件、主题 token、交互规范与无障碍检查。标识实际使用的专有格式和平台能力，先验证导出与可重建性；不为所有依赖建立多余抽象。

当需求、规模、部署、团队能力、许可或支持状态改变，或关键验证不通过时重新评估。迁移工作量取决于项目使用深度，尚未测量。
