## 它解决什么

组织文档接入、索引和检索应用。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：以企业文档检索与 RAG 为主。
- **职责边界**：答案准确性仍需评估；连接器许可另核。
- **选择分界**：以资料和检索需求选择连接器；权限过滤、引用依据和删除传播仍由业务验收。
- **比较入口**：直接检索实现；其他 RAG 框架。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[LangGraph](tech-langgraph.md)、[React Flow](tech-react-flow.md)。同域不等于等价，不必同时引入。

## 接入前提与接口

| 项目 | 接入时需要明确 |
|---|---|
| 建议能力接口 | 任务/资料/工具结果 → 状态化执行、检索或流程画布；这是业务职责示意，不是官方 API 签名 |
| 当前项目复用 | 检查已有实现、直接/传递依赖、锁文件、调用位置与平台原生能力 |
| 兼容重点 | 工具授权、状态恢复、引用、权限和外部动作幂等 |
| 目标版本 | 固定产品/发行版/版本，再核查文档；HEAD 不代表应直接用于生产 |
| 运行责任 | 谁提供运行环境、数据、权限、错误处理与长期维护 |

## 最小验证与验收重点

**决定性验证**：标注问题验证引用、权限与检索召回。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：解析、嵌入、存储、模型与服务费用。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：提示、schema、状态、工具接口、资料与执行记录。标识实际使用的专有格式和平台能力，先验证导出与可重建性；不为所有依赖建立多余抽象。

当需求、规模、部署、团队能力、许可或支持状态改变，或关键验证不通过时重新评估。迁移工作量取决于项目使用深度，尚未测量。
