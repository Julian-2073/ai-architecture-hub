# Blender

> 3D 创作软件 · 三维与实时场景 · 候选，尚无本项目采用结论。

[返回索引](../../docs/technology-catalog.md) · [能力地图](../capabilities/cap-software-map.md) · [选型判断](../../docs/technology-selection.md)

## 它解决什么

建模、材质、动画与离线渲染。官方资料入口供复核基本定位；以下适用性、接入和验证内容是选型建议，不是全部经过实测的产品承诺。

## 何时选，何时不选

- **适用条件**：制作产品或数字孪生的三维资产。
- **职责边界**：不是直接嵌入浏览器的实时 UI 库。
- **选择分界**：保留可编辑工程和通用导出资产；浏览器不能直接把离线渲染性能当实时运行能力。
- **比较入口**：其他建模软件；采购模型资产。先比较同层能力；不同层只能作为组合，不能因为名称都叫平台就直接替换。
- **相邻卡片**：[Three.js](tech-threejs.md)、[Babylon.js](tech-babylonjs.md)、[Godot](tech-godot.md)。同域不等于等价，不必同时引入。

## 接入前提与接口

| 项目 | 接入时需要明确 |
|---|---|
| 建议能力接口 | 模型/材质/场景状态 → 资产或实时场景；这是业务职责示意，不是官方 API 签名 |
| 当前项目复用 | 检查已有实现、直接/传递依赖、锁文件、调用位置与平台原生能力 |

| 目标版本 | 固定产品/发行版/版本，再核查文档；HEAD 不代表应直接用于生产 |
| 运行责任 | 谁提供运行环境、数据、权限、错误处理与长期维护 |

## 最小验证与验收重点

**决定性验证**：制作小模型导出 glTF 并验证 Web 加载。

只有结果会改变选型时才单独做 PoC；事先写明代表性数据、目标设备/环境、通过标准、停止条件与复现方式。目前未执行。

接入后的验证覆盖实际受影响行为：输入到输出是否正确、权限是否生效、失败能否解释或恢复、数据是否持久化或成功回读。性能指标使用实际负载，不从官方宣传推断。

## 成本与维护

主要成本驱动：建模人力、渲染资源与资产许可。按接入人力、固定资源、按量费用和维护分账；模型、托管服务、插件、素材与企业能力另核。没有单价和规模时不估金额。

维护核查：尚未综合核查发布、支持政策、issue 和安全公告。不能由正文可访问或 star 数推出“成熟可靠”。

## 退出与重新评估

建议保留：模型源文件、通用交换资产、场景和业务接口。标识实际使用的专有格式和平台能力，先验证导出与可重建性；不为所有依赖建立多余抽象。

当需求、规模、部署、团队能力、许可或支持状态改变，或关键验证不通过时重新评估。迁移工作量取决于项目使用深度，尚未测量。

## 如何调用、交付什么

**调用类型**：创作软件与独立处理进程。

官方命令行支持后台运行、运行Python脚本与渲染指定帧。选择UI、脚本或批处理取决于当前可用接口与资产任务。

| 交接项 | 需要落实 |
|---|---|
| 输入 | 有授权的工程/模型资产、脚本或明确操作、输出目录与渲染/导出设置 |
| 输出 | 可编辑工程、渲染图片/视频或指定交换资产；网页实时展示还需运行层接入 |
| 验收 | 核对工程可打开、实际输出文件、材质/单位/纹理及目标加载；进程退出不证明目标资产正确 |
| 保留与接入责任 | 保留源工程、素材许可、脚本和参数。先确认本机路径/版本与实际入口，原件之外输出，避免意外覆盖。 |

调用形式见[社区版来源登记](../../evidence/curation/tech-blender.json)；输入、交接与验收建议见[社区版来源登记](../../evidence/curation/tech-blender.json)。未在本轮安装、运行或验收该工具；官方支持与本次可调用性分开。
