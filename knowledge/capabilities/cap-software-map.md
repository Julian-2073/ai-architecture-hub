# 软件能力地图：从业务任务找到技术职责

本地图覆盖 32 个常见能力域；覆盖 Web、移动、桌面、数据、AI 与运行工程，不宣称穷尽软件行业。嵌入式、操作系统、工业控制、医疗、金融核心等领域还需要专门知识与规则。收录技术是发现入口，不代表统一推荐、成熟度背书或必须安装。

## 阅读路径

1. 用一句话写出用户完成什么任务，而不是先写框架名。
2. 在下表找到主能力，再沿数据流寻找必要的支撑能力。
3. 到 [技术卡片索引](../../docs/technology-catalog.md) 读取有关卡片；最终候选才进入当前官方资料调查。
4. 用 [选型判断指南](../../docs/technology-selection.md) 判断是否需要新依赖；按 [模板导航](../../docs/templates.md) 选择最小文档。

## 技术类型：名称相似不代表职责相同

| 类型 | 承担的职责 | 接入后仍需完成 |
|---|---|---|
| 语言 / 类型系统 | 表达逻辑、提供编译或检查能力 | 运行时校验、业务建模与部署 |
| 库 | 可被程序调用的局部能力 | 调用组织、输入输出、错误处理 |
| 框架 | 组织应用与执行约定 | 领域规则、数据与目标环境适配 |
| UI 组件库 | 标准化界面部件 | 产品流程、主题、权限、无障碍验证 |
| Headless 工具 | 状态或行为逻辑 | UI、交互细节和样式实现 |
| 编辑器 / 创作软件 | 制作内容或资产 | 存储、授权、发布和运行集成 |
| 引擎 / 求解器 | 执行渲染、搜索或优化等核心任务 | 数据建模、约束、质量和结果解释 |
| 数据库 / 存储 | 管理状态、查询与持久化 | schema、权限、备份、恢复和运维 |
| 协议 / 标准 | 定义交换和互操作规则 | 具体实现、超时、兼容性及安全 |
| SDK | 封装服务或平台调用 | 服务授权、错误处理、费用和退出策略 |
| 托管平台 | 提供由供应商运行的能力 | 配额、服务条款、地区、备份与迁移 |
| 工程工具 | 支持构建、测试、配置与排错 | 有意义的验收目标与工程责任 |

## 跨域能力：不能漏在工具之间

- **权限**：登录只证明身份；租户、对象、字段、文件与检索结果仍要分别授权。前端隐藏按钮不是权限控制。
- **国际化与时间**：字符、语言、时区、币种、小数、工作日和日期范围影响数据语义；选择 UI 库不能自动解决。
- **离线与同步**：本地缓存、冲突合并、重放、删除传播和恢复需要明确策略；有 CRDT 也不能省略业务规则。
- **可访问性**：语义、焦点、键盘、读屏与色彩需在真实流程验证；组件宣传不等于应用合格。
- **数据生命周期**：采集依据、保留、备份、导出、删除、审计和迁移应有负责人；敏感数据不能默认上传外部服务。
- **费用与可维护性**：接入人力、固定资源、按量、故障处理和退出分别计算；不要只比较订阅价。
- **供应链**：直接依赖、传递依赖、构建下载、容器镜像、模型权重、字体和素材分别核查版本及许可。
- **性能**：数据规模、并发、设备、网络、缓存与使用方式决定表现；官网吞吐不能套作本项目验收值。

## 连接关系：每条箭头都应有输入、输出和失败策略

| 数据流 | 各段职责 | 容易遗漏的工作 |
|---|---|---|
| 输入 → 校验 → 规则 → 事务存储 → 页面 | 表单、schema、业务服务、数据库、查询缓存 | 客户端与服务端重复校验的边界；提交成功回读 |
| 事件 → 采集 → 聚合 → 推送 → 图表 | SDK/API、任务或 SQL、SSE/WebSocket、图表库 | 事件口径、去重、迟到数据、断线补偿 |
| 文档 → 解析 → 切分 → 索引 → 检索 → 回答 | 文件处理、嵌入、检索系统、模型调用 | 资料权限、引用支撑、过期、删除传播与评估 |
| 模型资产 → 渲染 → 状态同步 → 场景交互 | Blender、Web 3D/引擎、业务接口 | 资产许可、单位、模型体积与设备能力 |
| 历史数据 → 时间切分 → 基线 → 预测 → 决策 | 数据处理、预测工具、优化或规则 | 泄漏、误差与业务收益分离；反馈与重训 |
| 业务事务 → outbox/任务 → 消费 → 外部动作 | 数据库、队列、Worker、外部 API | 幂等、重试、补偿、审计和授权 |

SSE 适合评估服务端单向事件推送；双向交互再评估 WebSocket。允许延迟且负载很小的场景，轮询可能更简单。三者均需验证认证、断线、代理和状态一致性。

## 先判断是否真的要升级技术

| 现状 | 优先动作 | 升级技术的证据 |
|---|---|---|
| 标准组件已覆盖需求 | 直接复用并验收业务行为 | 代表性功能或性能不能满足 |
| 单机数据量和写并发低 | 评估文件或 SQLite 等简单方案 | 并发、恢复、共享访问约束发生变化 |
| 单次模型调用已能完成任务 | 保持简单调用与可测输入输出 | 多步状态、失败恢复或人工介入确实需要 |
| SQL 能满足检索或关系查询 | 先优化模型、索引和查询 | 真实负载与查询模式证明边界 |
| 一个服务即可交付 | 保持单体或模块化单体 | 独立伸缩、部署或团队边界有明确收益 |
| 平台已有认证、存储、任务 | 核查原生能力并复用 | 功能、地区、许可或退出约束不满足 |

这不是为简单方案背书到底；一旦硬约束不满足，就对实际缺口调查，不把整个系统一起重选。
