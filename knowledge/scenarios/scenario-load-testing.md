# 知道多少人同时用会卡

ID：`scenario-load-testing`。这是一条任务发现与交接规则，不是已完成的软件或技术采用决定。

## 业务描述入口

多少人 / 并发 / 压力 / 很多人 / 大量请求；同时 / 卡 / 容量 / 测试 / 性能 / 承受。

## 先判断什么

先检查当前项目相关实现、依赖和平台能力；现有方案够用时复用，不因匹配到场景就新增框架。

先复用当前栈；对同职责候选作比较，对跨职责组件明确接口。列表不是全部要安装的技术栈。

- 获授权的测试环境是什么？
- 代表性负载和延迟错误率目标是什么？

## 技术职责与候选

- [k6](../technologies/tech-k6.md)：以脚本施加请求负载并观察指标。
- [Prometheus](../technologies/tech-prometheus.md)：抓取、存储和查询时间序列指标。

## 模块与数据流

工作负载 → 施压 → 服务指标 → 容量与瓶颈解释。

## 实现后应观察

- 负载可复现且数据安全
- 不把单次压测当永久保证
