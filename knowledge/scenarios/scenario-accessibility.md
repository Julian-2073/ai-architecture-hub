# 让键盘和读屏也能使用

ID：`scenario-accessibility`。这是一条任务发现与交接规则，不是已完成的软件或技术采用决定。

## 业务描述入口

键盘 / 读屏 / 屏幕阅读器 / 无障碍 / 残障；使用 / 操作 / 检查 / 支持 / 访问。

## 先判断什么

先检查当前项目相关实现、依赖和平台能力；现有方案够用时复用，不因匹配到场景就新增框架。

先复用当前栈；对同职责候选作比较，对跨职责组件明确接口。列表不是全部要安装的技术栈。

- 关键用户流程与目标辅助工具是什么？
- 是否有明确适用标准？

## 技术职责与候选

- [axe-core](../technologies/tech-axe-core.md)：自动检查部分网页可访问性规则。自动化规则只覆盖部分无障碍问题；关键任务还需键盘与读屏等人工检查，不能以零告警宣称完整合规。
- [Radix Primitives](../technologies/tech-radix.md)：构建对话框、菜单等基础交互。

## 模块与数据流

语义组件 → 键盘焦点 → 自动检测 → 人工读屏。

## 实现后应观察

- 关键任务可完成
- 自动检查不能代替人工验证
