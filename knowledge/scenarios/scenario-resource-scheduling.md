# 安排机器和人员且时间不冲突

ID：`scenario-resource-scheduling`。这是一条任务发现与交接规则，不是已完成的软件或技术采用决定。

## 业务描述入口

机器 / 工人 / 人员 / 设备 / 排班 / 排产；安排 / 不能撞 / 不冲突 / 约束 / 工序 / 调度 / 计划。

## 先判断什么

先检查当前项目相关实现、依赖和平台能力；现有方案够用时复用，不因匹配到场景就新增框架。

先复用当前栈；对同职责候选作比较，对跨职责组件明确接口。列表不是全部要安装的技术栈。

- 必须满足哪些硬约束？
- 优化目标、求解时间和无解处理是什么？

## 技术职责与候选

- [OR-Tools](../technologies/tech-ortools.md)：约束规划、路由与组合优化。

## 模块与数据流

订单与资源 → 约束模型 → 求解 → 独立约束校验 → 排程解释。

## 实现后应观察

- 硬约束独立检查通过
- 无解和超时不伪装成最优
