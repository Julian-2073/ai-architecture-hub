# 从期望效果到技术路径

读取本 Skill 目录中的 `hub-location.json`，将其中 root 相对该目录解析为知识库绝对路径。安装器会为安装后的 Skill 写入本机路径，仓库内版本使用相对位置。知识库不可访问时说明缺口并继续理解需求，不扩大扫描、不自动重建或安装。

首次按需阅读知识库的 `docs/novice-workflow.md`。用户只需说明目的、操作、输入和希望看到的效果，不必知道组件名或填写 JSON。

调用知识库绝对路径中的 `scripts/kb.py discover '用户原话' --json`，用 Python 3 执行；有已核实的目标项目时加 `--project`。读取相关卡片、实现路径和失败经验，优先复用项目已有组件及平台能力。

词组未命中或匹配不合理时，用当前 Codex 的理解继续拆解并按能力检索；必要时提供有原话引用的 `--intent-json`。区分已知约束、推断和排除项，不能把规则未命中当作没有成熟方案。只询问会改变方向的关键缺口。

对实际技术缺口核查当前官方文档与仓库，比较同职责候选，明确需要组合的不同层。最终路线检查目标版本、许可、环境、成本与迁移；只对改变选择的关键风险做 PoC。

交接解释为什么这样构建、替代路径的代价和什么变化会重新选型，给出模块、数据流、接口、任务与验收。候选、配方、环境中发现可执行文件和项目实测分别说明。

`discover` 仅只读发现，不安装、不生成或部署应用。实施任务在已有授权内继续编码、测试和审查；讨论及明确只读任务不回写。用户授权的项目复盘才记录有证据的经验，不公开私人材料，不把历史或模拟验收改为当前真实业务成果。
